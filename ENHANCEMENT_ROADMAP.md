## 🔴 CRITICAL — Fix Before Any Public Release (9 Issues)

### 1. Hardcoded Mock IDs `customer1` in Live DB Queries
**6 files** use `'customer1'` as a real `customer_id` in Supabase queries — calendar, appointments, search, account, support model, event model. Every query will either return no data (production DB has no `customer1`) or pull the wrong user's data.
> **Fix:** Replace with `Supabase.instance.client.auth.currentUser?.id ?? ''`

### 2. `default_vendor` Placeholder in Production Routes
`app_routes.dart` L106–251 — vendor booking management and vendor request management screens receive a fake `Vendor(id: 'default_vendor')`. Any Supabase query with this ID will fail or return empty results silently.
> **Fix:** Read vendor profile ID from the authenticated session at runtime.

### 3. API Key Sent in Client Request Body to Edge Function
`payment_service.dart` L41, 186 — `'apiKey': BillplzConfig.apiKey` is passed inside the Edge Function body. This is visible in network traffic. The Edge Function should read the key from its own Supabase Secrets environment — the client body should never contain secrets.

### 4. Third-Party CORS Proxy (`corsproxy.io`) for Payment Status Checks
`payment_service.dart` L118, 370 — Billplz and Xendit invoice status checks on web route through `corsproxy.io`, exposing auth headers and payment response data to a third-party server.
> **Fix:** Route `getBill()` and `getXenditInvoice()` through dedicated Supabase Edge Functions.

### 5. Chat `senderId: 'current_user_id'` Hardcoded
`guest_chat_screen_fixed.dart` L36 — All guest messages are attributed to the literal string `'current_user_id'`.
> **Fix:** Replace with `SupabaseService.currentUser?.id`.

### 6. Both Payment Gateways Still in **Sandbox Mode** at Compile-Time
`lib/core/config/billplz_config.dart` L9: `isSandbox = true`  
`lib/core/config/xendit_config.dart` L7: `isSandbox = true`  
These are hard-coded `const` booleans. Shipping to production while these are `true` means **all real payments hit the sandbox and are not collected**.
> **Fix:** Load `BILLPLZ_IS_SANDBOX` and `XENDIT_IS_SANDBOX` from `.env` using `flutter_dotenv`, or use a build-flavor system.

### 7. Xendit API Key is a Literal Placeholder (`xnd_development_YOUR_SANDBOX_SECRET_KEY`)
`xendit_config.dart` L3 and the Edge Function `create-xendit-invoice/index.ts` L27 both contain the literal string `xnd_development_YOUR_SANDBOX_SECRET_KEY`. The Edge Function has a hardcoded fallback to this string — if the environment secret is missing, invoices will be created against a dummy key and silently fail in production.

### 8. `softDeleteAccount()` Does Not Remove Supabase Auth Record
`security_service.dart` L30–52 — sets `deleted_at` in the `users` table and signs out, but never calls `supabase.auth.admin.deleteUser()`. Apple App Store policy **requires** complete account deletion. This is a binary rejection risk.
> **Fix:** Call a privileged Supabase Edge Function (using Service Role Key) to fully purge the auth record.

### 9. Payment Transaction State Is Never Persisted to the Database
`payment_provider.dart` — `PaymentTransaction` objects are stored only in memory (`_transactions = []`). If the app is restarted after the payment gateway redirect, all transaction state is lost. Users may be charged but the app has no record.
> **Fix:** Persist each `PaymentTransaction` to a `payment_transactions` Supabase table immediately on creation, and load from DB on startup.

## 🟠 IMPORTANT — Fix Before Stable v1.0 (11 Issues)

### 10. `https://eventease-app.com/payment/callback` — Non-Existent Domain
Found in 4 files:
- `payment_provider.dart` L138, L164
- `subscription_provider.dart` L140
- `customer_subscription_provider.dart` L160, L184

All Billplz and Xendit callback/redirect URLs point to `https://eventease-app.com/payment/callback` which is a placeholder domain. Payment gateway callbacks will fail silently in production — vendors will never receive payment confirmations.
> **Fix:** Set up a real webhook handler URL (or a Supabase Edge Function URL) and replace all 5 occurrences.

### 11. All 5 Edge Functions Use Wildcard CORS (`'*'`)
`create-xendit-invoice`, `create_billplz`, `create_payout_billplz`, `payment-webhook`, `xendit-webhook` all respond with `Access-Control-Allow-Origin: '*'`.  
For payment and webhook endpoints this means any website in the world can call them with a valid Supabase anon key.
> **Fix:** Restrict to your production domain: `Access-Control-Allow-Origin: https://your-domain.com`.

### 12. `cancelBooking()` Sends No Notification
`booking_provider.dart` L554 — calling `cancelBooking()` just calls `updateBookingStatus(bookingId, cancelledByUser)`. The vendor receives no notification that a booking was cancelled. Compare with `acceptBooking()` and `rejectBooking()` which do trigger notifications.

### 13. `refundPayment()` Only Updates In-Memory State
`payment_provider.dart` L192–194 — `refundPayment()` calls `updatePaymentStatus()` which only mutates the local `_transactions` list. No actual refund API call is made to Billplz/Xendit, and no DB record is updated. 
> **Fix:** Call the appropriate gateway refund endpoint via an Edge Function.

### 14. Email & SMS Notification Methods Are Empty Stubs
`notification_service.dart` L619–629 — both `_sendEmail()` and `_sendSMS()` only `print()`. Users who enable email/SMS in settings receive nothing.

### 15. `getPendingVendorChanges()` Uses N+1 Query Pattern
`booking_provider.dart` L490–518 — fetches pending changes by looping over each `changeRequested` booking individually, issuing one `getBookingChanges()` call per booking. This is an N+1 query problem. With 100 pending bookings, this fires 100 sequential DB requests.
> **Fix:** Use a Supabase join query: `booking_changes.select('*, bookings!inner(vendor_id)').eq('bookings.vendor_id', vendorId).eq('status', 'pending')`.

### 16. `createInstallmentPlan()` Issues N+1 Inserts for Payment Schedule
`booking_provider.dart` L257–267 — inserts installment payment records one-by-one in a for loop. Use `supabase.from('installment_payments').insert(list)` for a single bulk insert call.

### 17. Debug Screens (`/__debug/*`) Are Registered in Production Routes
`app_routes.dart` includes `VendorScreensGalleryScreen.routeName` (`/__debug/vendor-screens`) and `OrganizerScreensGalleryScreen.routeName` (`/__debug/organizer-screens`). Anyone who knows these URLs can access them in production builds.
> **Fix:** Wrap the registration with `if (kDebugMode)` or remove entirely from production.

### 18. `flutter_skill` Package Imported Unconditionally in `main.dart`
`main.dart` L6: `import 'package:flutter_skill/flutter_skill.dart'` — the import is at the top of the file regardless of `kDebugMode`. The binding is only initialized in debug (`L92`), but the package is always compiled in. This is an AI development tool that should not ship in release builds.
> **Fix:** Move `flutter_skill` to `dev_dependencies` and use conditional imports, OR remove the import from release flavor.

### 19. Numerous Core Routes Still Point to `SplashScreen` as Placeholder
`app_routes.dart` L172–176 — `/search`, `/bookings`, `/profile`, `/settings` all navigate to `SplashScreen`. These are called from the home navigation bar.

### 20. Guest Module — Multiple `TODO` Features Permanently Incomplete
Meal preferences never saved, seating status always `false`, share/calendar/maps/directions all `TODO`, digital wallet not implemented, anonymous name in gift registry. These represent the entire guest user experience being partly non-functional.

## 🟡 QUALITY / PERFORMANCE — Address Before Stable (11 Issues)

### 21. 40+ `via.placeholder.com` Image URLs in Production-Facing Code
Found across `catering_services.dart`, `enhanced_sample_data.dart`, `shop_screen.dart`, `rental_management_screen.dart`, `vendor_networking_provider.dart`, `photo_album.dart`, `gift_registry.dart`, and more. These placeholder images appear to users in the shop, rentals, and vendor listings.

### 22. `via.placeholder.com` Used for Map View in `event_map_screen.dart`
`event_map_screen.dart` L48 — the map screen shows a `NetworkImage('https://via.placeholder.com/400x250?text=Map+View')` instead of a real map. The `google_maps_flutter` dependency is declared but the Google Maps API key is never configured in `AndroidManifest.xml` or `web/index.html`.

### 23. `PaymentTransaction` Model Has No `copyWith` — Manual Reconstruction Required
`payment_provider.dart` L62–63 — the developer left a comment acknowledging `copyWith` is missing and manually reconstructs the entire object on every status update. This is fragile and error-prone.

### 24. Session ID Uses `.hashCode` — Not Collision-Safe
`security_service.dart` L69: `final sessionId = _client.auth.currentSession?.accessToken.hashCode.toString()` — Dart's `hashCode` is not unique across sessions and can collide. Use the JWT `jti` claim instead.

### 25. Unread Notification Count Fetches All Rows
`notification_service.dart` L783–792 — fetches all unread notification IDs and measures the list length client-side. At scale this wastes bandwidth. Use Supabase `count()` aggregation.

### 26. Realtime Notification Stream Has No Index Check — Popup on Stale Data
`notification_provider.dart` L116–126 — shows a local popup for any notification less than 10 seconds old. On re-login or re-initialization, existing recent-but-read notifications may trigger spurious popups.

### 27. Dual HTTP Client Dependencies — `http` and `dio` Both Present
`pubspec.yaml` L67–68 — both are declared. Adding ~200 KB of dead code if only `http` is used.

### 28. Both `provider` and `get` (GetX) Declared Simultaneously
`pubspec.yaml` L46–47 — two state management frameworks is an anti-pattern.

### 29. `hive` Dependencies Declared, No Usage Found
`hive`, `hive_flutter`, `hive_generator` declared — no `Hive.openBox()` call found in the codebase. Likely vestigial.

### 30. Xendit Edge Function Fallback Key in Source Code
`create-xendit-invoice/index.ts` L27 — `Deno.env.get('XENDIT_SECRET_KEY') || 'xnd_development_YOUR_SANDBOX_SECRET_KEY'` — if the secret is missing from the Supabase project, all invoice creation silently uses the placeholder key and returns 401 errors. Remove the fallback so failures are explicit.

### 31. `SupabaseService` Stores Anon Key and URL as Plain `const` Strings
`supabase_service.dart` L8–10 — `supabaseUrl` and `supabaseAnonKey` are hardcoded constants in source code. While the anon key is publicly safe, combining it with hardcoded URL in source means rotating the URL/key requires a full app republish. Load from `.env` via `flutter_dotenv` (which is already a dependency).
